## The missed product work

The client pages connect a specific search intent to installation, authorization, examples, documentation and a product CTA. Their shared structure is reusable, but named-client compatibility still needs real verification. PostDelegate currently has much of the underlying REST/MCP functionality but not this public onboarding and discovery layer.

A useful first expansion is a public MCP hub, REST API hub, and tested guides for the actual clients our target users use. Add a short draft-to-approved-to-scheduled tutorial, large-media upload instructions, permission choices and recovery examples. Then add supported-platform pages, a few functioning utilities, and a small number of honest comparisons.

Do not imitate the directory size as a success metric. The observed 243 tool links, 63 comparison links and 12 alternatives links describe page coverage, not verified functionality, indexing, traffic, conversion or revenue.

## Claude Cowork specifically

The linked page is a dedicated acquisition and onboarding page, not just a mention of MCP in a feature list. It presents an agent skill/CLI, configuration, examples and links to source documentation. PostDelegate should provide its own verified route from client setup to an observable draft in the web workspace; a logo and a generic endpoint alone are insufficient. No PostDelegate Cowork workflow has been claimed verified by this audit.

## Limitations

The npm website returned a bot check; package metadata was read from the public npm registry without installation. Make and Enterprise content were read through web fallbacks after browser difficulties. Affiliate routing and status-monitor values are observations from this session, not a claim those destinations are universally broken. All named-client pages were read, but their installation steps were not executed.
